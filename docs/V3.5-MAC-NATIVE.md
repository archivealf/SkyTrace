# SkyTrace V3.5 Mac Native

V3.5 is the desktop-focused SkyTrace release. It keeps the existing V3.4 aviation, Cloud, Commerce, Operations and Replay functionality and adds a macOS-native integration layer without requiring the paid Apple Developer Program.

## Included Mac upgrades

- macOS menu-bar status with visible aircraft, watchlist hits, alert pause, Settings, Airport Desk and Command Centre shortcuts.
- Native Notification Center aircraft alerts. Clicking a notification focuses SkyTrace and searches for the matching aircraft.
- Proper Settings window instead of using `config.json` as the primary preferences interface.
- Optional Launch at Login.
- `Cmd+K` Command Centre plus `Cmd+1` through `Cmd+4` workspace shortcuts.
- Private Local Replay stored under the user's SkyTrace Application Support directory with configurable retention and disk caps.
- Detached aircraft windows with live state, 24-hour private local history, altitude/speed profiles, flight-phase estimation and a clearly-labelled orbit/hold estimate.
- Full detached Airport Desk with observed nearby/ground/inbound/outbound traffic, runway-use estimates, type mix, runway/frequency reference, weather and movement estimates.
- High Accuracy, Balanced and Battery Saver performance profiles.
- Cached/degraded flight fallback when live traffic temporarily fails. Bundled airport/aircraft reference data remains available locally.
- Source layout cleanup: new desktop, renderer and build work lives under `src/` and is copied into the materialized runtime by the V3.5 layer.
- Ephemeral per-launch desktop API authorization using both an HttpOnly loopback cookie and an Electron network-layer request header. The token is never exposed to renderer JavaScript.
- Content Security Policy on the local SkyTrace server.
- A packaged renderer startup handshake, startup recovery guard and early diagnostic milestones so a broken local API cannot leave the app permanently covered by the loading screen.
- Intel and Apple Silicon CI packaging with ZIP/DMG artifacts and SHA-256 checksums.
- CI now launches the packaged `.app` itself and requires a healthy renderer + local API handshake before artifacts are accepted.

## No paid Apple signing

V3.5 intentionally does **not** require Developer ID signing or Apple notarization. This avoids the annual Apple Developer Program cost.

Because Electron's automatic macOS installer requires a suitable signed application, V3.5 keeps release checking but uses verified/manual GitHub release installation when the build is unsigned. ZIP and DMG artifacts still receive SHA-256 checksum files.

## Install / repair V3.5

The development installer preserves `config.json`, Mac settings and Private Local Replay, clears only disposable Electron caches, replaces the application, and runs the installed app in startup-test mode before reporting success.

```bash
bash <(curl -fsSL "https://raw.githubusercontent.com/archivealf/SkyTrace/v3.5-mac-native/install-v3.5-dev")
```

A successful installer must see the packaged renderer report `health=true`, `shell=true` and `degraded=false` before it opens SkyTrace normally.

## Materialize locally

```bash
export SKYTRACE_COMMERCE_URL="https://skytrace.duckdns.org"
bash scripts/materialize-v3.5.sh
npm install --no-audit --no-fund
npm run data
npm run icon:mac
npm run check
node src/build/verify-v35.mjs
npm run make:mac
```

The V3.5 materializer first builds the established V3.4 runtime, then applies the new canonical files from `src/desktop` and `src/renderer`, hardens the loopback desktop API and verifies the resulting V3.5 runtime.

## Startup diagnostics

The runtime log is:

```text
~/Library/Logs/SkyTrace/desktop.log
```

Read it with:

```bash
cat "$HOME/Library/Logs/SkyTrace/desktop.log"
```

The installer log is:

```text
~/Library/Logs/SkyTrace/installer.log
```

The previous diagnostic pattern `find ~/Library -iname '*skytrace*' -type f` is not suitable for locating `desktop.log`, because `-iname` matches the file's basename rather than the `SkyTrace` directory in its path.

## Local Replay privacy

Private Local Replay is separate from SkyTrace Cloud Replay. The V3.5 feature writes observations received by the local Mac to `local-replay.ndjson` under SkyTrace's Application Support directory. Users can disable it, choose retention, set a disk cap and delete it from Settings.

If the user is signed into features that already contribute observations to SkyTrace Cloud Replay, that existing Cloud behaviour remains separate; the Local Replay feature itself does not upload its local file.

## Operational-data wording

Airport arrival/departure, runway use, flight phase and orbit/holding values are derived estimates from observed public data. The UI keeps these values explicitly labelled as estimates and does not present them as licensed schedule, ATC or operational truth.
